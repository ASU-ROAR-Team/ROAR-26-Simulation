# dstar_navigation

An autonomous global path planner package for ROS 2 (Humble) implementing the **D* Lite** (Koenig & Likhachev) incremental replanning algorithm. 

It is designed for planetary rovers and field robotics to navigate through complex, static, and dynamic environments with continuous terrain roughness and elevation costs.

---

## 1. Package Function & Architecture

The package contains a core C++ planner node, a python-based path simulator for pure-pursuit trajectory execution, and a comprehensive test harness suite.

### Core Nodes:
1.  **`dstar_node` (C++)**:
    *   Exposes a standard ROS 2 Action Server for `/navigate_to_pose` (`nav2_msgs/action/NavigateToPose`).
    *   Subscribes to `/map` (`nav_msgs/OccupancyGrid`) and `/odom` (`nav_msgs/Odometry`).
    *   Publishes the optimal trajectory on `/global_plan` (`nav_msgs/Path`).
    *   Detects costmap changes dynamically, running fast incremental updates rather than full replans, with an A* traceback fallback for safety.
2.  **`path_simulator` (Python)**:
    *   Simulates the robot's kinematics and movement along the published global plan.
    *   Implements a stable **lookahead pure-pursuit controller** to prevent backward oscillations.
    *   Publishes the simulated robot's `/odom` and broadcasts coordinate frame transforms (`map` -> `odom` -> `base_link`).

## 2. Input Map Topics, Data Formats & Weights

The D* Global Planner accepts multiple input map layers to evaluate 2D obstacles, 3D elevation geometry, and surface roughness simultaneously:

| Map Data Type | Default Topic | Topic Parameter | Message Type | Purpose & Data Format | Key Parameters & Cost Weights |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Occupancy Grid** | `/map` | `map_topic` | `nav_msgs/msg/OccupancyGrid` | 2D obstacle grid (`-1` = unknown, `0..99` = cost, `100` = lethal). Defines base graph geometry & clearance. | `lethal_cost_threshold: 253`<br>`unknown_traversal_cost: 2.0`<br>`corridor_penalty_scale: 1.0`<br>`enable_clearance_cost: true`<br>`clearance_cost_weight: 5.0` |
| **Heightmap** | `/active_map/heightmap` | `heightmap_topic` | `nav_msgs/msg/OccupancyGrid` | Min-max normalized (0–100) elevation map. Decoded into real meters $Z$ for 3D step & slope checks. | `max_traversable_height_diff: 0.30` (m)<br>`max_traversable_slope_deg: 25.0` (°)<br>`enable_slope_cost: true`<br>`slope_cost_weight: 3.0` |
| **Heightmap Range** | `/active_map/heightmap_range` | `heightmap_range_topic` | `std_msgs/msg/Float32MultiArray` | `[h_min, h_range]` float array in meters. Decodes normalized heightmap cells back to absolute meters. | `occupancy_heightmap_scale: 0.05` (fallback decoding scale) |
| **Terrain Costmap** | `/terrain_costmap` | `terrain_costmap_topic` | `nav_msgs/msg/OccupancyGrid` | Surface roughness (Laplacian filter) & local gradient (Sobel filter) generated by `heightmap_to_costmap.py`. | `enable_terrain_costmap: true`<br>`terrain_costmap_weight: 2.0` |
| **Robot Odometry** | `/odom` | — | `nav_msgs/msg/Odometry` | Provides current robot pose for plan initialization and replan start snapping. | — |

### Edge Cost Formula
The total cost to traverse between adjacent grid cells $A \to B$ combines distance with weighted cost terms:
$$\text{Cost}(A \to B) = \text{distance} \times \Big(1.0 + \text{corridor\_term} + \text{clearance\_term} + \text{slope\_term} + \text{terrain\_term}\Big)$$

Where:
* $\text{slope\_term} = \text{slope\_cost\_weight} \times \left(\frac{\theta_{\text{deg}}}{\text{max\_slope}}\right)^2$
* $\text{terrain\_term} = \text{terrain\_cost\_weight} \times \left(\frac{\text{cost}_{\text{terrain}}}{100.0}\right)^2$

## 3. Configuration Parameters (`config/dstar_params.yaml`)

The planner's behavior is controlled by parameter definitions loaded at runtime:

| Parameter | Type | Default | Description |
|:---|:---:|:---:|:---|
| `lethal_cost_threshold` | `int` | `253` | Cost values $\ge$ this threshold are treated as impassable/lethal obstacles (maximum is 254). |
| `unknown_traversal_cost` | `double` | `2.0` | Cost multiplier for traversing through unknown (`NO_INFORMATION` / 255) cells. |
| `allow_unknown` | `bool` | `true` | If true, the robot is permitted to plan routes through unknown regions. |
| `heuristic_weight` | `double` | `1.0` | Heuristic scale. **Must be 1.0** to guarantee admissible and consistent D* Lite key updates. |
| `corridor_penalty_scale` | `double` | `1.0` | Scale weight for continuous terrain cell cost values (favoring cheaper detours). |
| `enable_clearance_cost` | `bool` | `true` | Enables inflation-based obstacle clearance. |
| `clearance_cost_weight` | `double` | `5.0` | Penalization weight for steering the robot away from obstacle edges. |
| `enable_clearance_field` | `bool` | `false` | Enables decay-based potential field clearance. |
| `clearance_field_weight` | `double` | `2.0` | Weight for the potential field decay term. |
| `enable_slope_cost` | `bool` | `true` | Enables quadratic penalty for steep slope traversal. |
| `slope_cost_weight` | `double` | `3.0` | Cost multiplier for slope angle term. |
| `max_traversable_slope_deg` | `double` | `25.0` | Maximum traversable slope in degrees. Angles above this are hard-pruned. |
| `enable_height_diff_cost` | `bool` | `true` | Enables hard cliff/step height pruning. |
| `max_traversable_height_diff` | `double` | `0.30` | Maximum vertical step height in meters. Steps above this are hard-pruned. |
| `enable_terrain_costmap` | `bool` | `true` | Enables surface roughness / steepness cost layer from `/terrain_costmap`. |
| `terrain_costmap_weight` | `double` | `2.0` | Cost multiplier for terrain roughness layer. |
| `enable_incremental_updates` | `bool` | `true` | Enforces D* Lite incremental graph repair (set false to force full A* replans). |
| `debug_publish_costmap` | `bool` | `true` | Publishes visual cost overlays on `/debug_costs` for RViz. |

## 4. How to Build & Launch

### Build the Package:
Source your ROS 2 environment, navigate to your workspace root, and run:
```bash
colcon build --packages-select dstar_navigation
source install/setup.bash
```

### Module Bringup (Standalone)
Use these to run each module independently for development or integration testing:
```bash
# Global planner standalone (D* Lite + simulated map + path follower + RViz)
./run_global.sh
./run_global.sh map_scenario:=lidar_maze_120 start_x:=1.0 start_y:=1.0

# Local controller standalone (MPPI, waits for /global_plan)
./run_local.sh

# Full stack (D* Lite + MPPI integrated)
./run_both.sh
```

Or launch directly via `ros2 launch`:
```bash
ros2 launch dstar_navigation bringup_global_planner.launch.py map_scenario:=open
ros2 launch dstar_navigation bringup_local_controller.launch.py
ros2 launch dstar_navigation bringup_full_stack.launch.py
```

### Test Suite Launch Configurations:
*   **Static Test (Phase 1)**:
    ```bash
    ros2 launch dstar_navigation test_static.launch.py scenario:=wall
    ```
*   **Dynamic Maze Test (Phase 2)**:
    ```bash
    ros2 launch dstar_navigation test_dynamic.launch.py scenario:=known_maze_blocked
    ```
*   **Hybrid Detour Test (Phase 3)**:
    ```bash
    ros2 launch dstar_navigation test_hybrid.launch.py scenario:=corridor_block
    ```
*   **Terrain Cost Test (Phase 4)**:
    ```bash
    ros2 launch dstar_navigation test_terrain.launch.py scenario:=gradient_slope
    ```
*   **ERC Marsyard Canyons (Phase 5)**:
    ```bash
    ros2 launch dstar_navigation test_erc.launch.py
    ```
*   **Near-Goal Fallback Test (LiDAR style)**:
    ```bash
    python3 test/run_fallback_test.py
    ```
*   **Multi-Waypoint Navigation (Complex ERC Map)**:
    ```bash
    python3 test/run_waypoints_test.py
    ```
